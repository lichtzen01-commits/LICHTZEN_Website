# 해외 수출 주문 처리 흐름 (FX 인보이스 건 기준)

구글 드라이브의 한 주문 폴더(예: `FX#202`)를 분석해 정리한 업무 순서입니다.
이 저장소는 공개 저장소이므로 거래처명·금액·계좌·담당자 이름은 적지 않습니다. 실제 값은 드라이브에만 둡니다.

## 폴더 구성 (주문 1건 = 폴더 1개, 폴더 이름 = 인보이스 번호)
| 순서 | 파일 | 만드는 쪽 | 내용 |
|---|---|---|---|
| 1 | `Order<날짜>.xlsx` | 고객 | 발주서(PO): 품목·Part#·수량·단가, 인도조건, 운송 방법, 포워더, 도착 공항, 받는 곳 |
| 2 | `<인보이스>_PI.pdf` | 리트젠 | 견적 송장(Proforma Invoice): 인보이스 번호·날짜, PO 번호, Bill to / Ship to, 결제 조건, 은행 정보, HS 코드, 출발 예정일 |
| 3 | `<고객>_램프 검수 리스트.xlsx` | 리트젠 영업 → 램프사업부 | 램프별 검수 기준: 모델, Part#, 수량, 발광장·전장(±0.5~1mm), 관경(±0.2~0.3mm), 좌우 리드선, 터미널, 베이스, 배기 방향, 라벨, 레이저 각인 |
| 4 | `<인보이스>_검수리스트.pdf` | 램프사업부 | 검수 완료본(손으로 체크한 스캔본) |
| 5 | `<인보이스>.xlsx` | 리트젠 | **작성창 시트 하나에 입력하면 PI·CI·PL 시트가 수식으로 채워지는 원본 파일** |
| 6 | `<인보이스>_CIPL.pdf` | 리트젠 | 상업 송장(CI) + 포장 명세서(PL): 박스 크기, 박스 수, 순중량/총중량 |
| 7 | `수출면장.pdf` | 관세사 | 수출신고필증: 신고번호, 수리일, **적재의무기한(수리일 +30일)**, FOB 금액, HS 코드 |
| 8 | `송금증.pdf` | 고객 | 대금 송금 확인(선결제 T/T) |
| 9 | `AWB.pdf` | 포워더 | 항공 운송장: AWB 번호, 항공편, 출발일, 운임 조건 |

## 진행 순서와 걸린 기간 (FX#202 실제 날짜 기준)
```
D+0  고객 발주(PO) 메일 수신
D+3  PI 발행 → 고객에게 송부 (선결제 요청)
D+3  검수 리스트 작성 → 램프사업부 전달 → 제작
D+7  검수 완료 (스캔 보관)
D+11 작성창 입력 → CI/PL 발행 → 관세사에 수출신고 의뢰 → 수출신고필증 수령
D+12 고객 송금 확인
D+13 포워더 픽업·출항 → AWB 수령 → 고객에게 선적 서류(AWB, CI/PL) 송부
```

## 작성창(원본 엑셀) 입력 항목
ATTN, Bill To(회사·주소), Ship To(회사·주소), 운송(포워더), 최종 목적지, PI/CI 출발일, 인보이스 번호·날짜,
PO 번호·날짜, 결제 조건, 인도조건(Incoterms), 비고, HS 코드, 품목(설명·수량·단위·단가·금액), 포장 크기, 박스 수(CTN/CRT), 중량.

작성창에 적힌 사내 규칙:
- 샘플이 있으면 "Non-commercial value for Samples #n" 문구를 넣는다.
- 인도향 서류에는 HG/FE/GA(램프 종류 표기)를 쓰지 않는다.
- 행은 지우지 말고 숨긴다(수식이 걸려 있음). 중량 칸은 띄어쓰기 없이 쓴다.
- CTN = 종이 박스, CRT = 나무 박스.
- HS 코드는 사내 NAS의 `해외영업/교육/HS코드리스트.xlsx`를 참고한다.

## 서류끼리 맞아야 하는 값 (자동 점검 후보)
| 값 | 나오는 서류 |
|---|---|
| 인보이스 번호 | PI, CI, PL, 수출신고필증(송품장부호), AWB |
| PO 번호·날짜 | PO, PI, CI, PL |
| 품목별 Part#·수량·단가·합계 | PO, PI, CI, 수출신고필증 |
| 총수량, 순중량/총중량, 박스 수 | PL, 수출신고필증, AWB |
| 결제 금액 | PI 합계, 송금증 |
| HS 코드 | PI, CI, 수출신고필증 |
| 출발일 | PI, CI(예정일), AWB(실제 항공편 날짜) |
| 받는 곳(Ship to) | PO, PI, CI, AWB |

FX#202에서 확인할 만한 점:
- 발주서에 Part#가 "unknown"인 품목 2개가 PI에서 채워졌다. 사람이 Part#를 확정하는 단계가 있다.
- 작성창 메모의 UV LAMP HS 코드 예시와 이번 신고에 쓴 HS 코드가 다르다. 품목별로 어느 코드가 맞는지 HS 코드 리스트로 확인이 필요하다.
- PI·CI의 출발일과 AWB의 실제 항공편 날짜가 하루 다르다(예정일과 실제일의 차이).
- 고객 발주서에 적힌 리트젠 우편번호가 옛 번호다.

## 자동화할 수 있는 단계 (계획)
| 단계 | 자동화 내용 | 방식 |
|---|---|---|
| 발주 메일 수신 | '발주'로 분류, 새 인보이스 번호로 드라이브 폴더 생성, PO 첨부 저장, 접수 확인 자동 답장 | Apps Script (Gmail·Drive) |
| PI 작성 | 고객 정보 표(Bill to·Ship to·결제 조건·포워더)와 Part# 표에서 작성창을 미리 채움 → 담당자 확인 → PDF 생성 | Apps Script (Sheets → PDF) |
| 검수 리스트 | Part#별 사양 표에서 검수 리스트 자동 작성 → 램프사업부에 메일 | Apps Script |
| 서류 대조 | PO·PI·CI·면장·송금 금액·수량·Part# 비교, 다르면 알림 | Apps Script (PDF 글자 추출은 한계 있음) |
| 기한 알림 | 적재의무기한(수리일+30일), 송금 미확인, 출발 예정일 알림 | Apps Script (매일 실행) |
| 진행 현황 | 주문별로 9개 서류 중 무엇이 있고 없는지 현황 시트 | Apps Script (Drive 폴더 확인) |
| 선적 통지 | AWB가 폴더에 들어오면 고객에게 AWB·CI/PL 첨부 메일 초안 | Apps Script (초안만, 발송은 사람이 확인) |

필요한 기준표(드라이브에 시트로 만들 것): 고객 정보 표, Part#·사양 표, HS 코드 표, 포워더 표.

## PI 작성 규칙 (FX#203 작성 때 확정)
원본 엑셀(작성창 + PI + CI,PL)을 복사해서 쓰고, **주문마다 아래 10가지만 바꾼다.** 나머지 칸·서식·이미지·은행 정보는 그대로 둔다.

| # | 칸 | 규칙 |
|---|---|---|
| 1 | 인보이스 번호 | FX#다음번호 |
| 2 | 인보이스 날짜 | **PI를 실제로 발행한 날**, `YYYY-MM-DD` |
| 3 | PO 번호 | 고객 발주서 파일 이름 (예: `Order20260611Re2`) |
| 4 | PO 날짜 | 발주서 날짜, `YYYY-MM-DD` |
| 5 | Remarks | 기본 문구(OUR 송금, 보증 1년) + 샘플·오리지널 램프 반환·교체품이 있으면 "Non-commercial value for …" 한 줄 |
| 6 | Departure date | **인보이스 날짜 + 달력 10일** (주말·공휴일 포함해서 셈), `YYYY-MM-DD` |
| 7 | 품명 | `n. UV LAMP (모델)` + 다음 줄 `   PART#번호`. 샘플은 `SAMPLE:`, 교체품은 `REPLACEMENT:`, 고객이 보낸 원본 램프는 `ORIGINAL LAMP RETURN` |
| 8 | 수량 | 발주서 수량 (취소 품목 제외) |
| 9 | 가격 | 발주서 단가. 샘플·교체품·반환품은 금액 칸에 `NON-COMMERCIAL` |
| 10 | Marks | 고객별 쉬핑마크(PPT)에 `PO NO. : <PO 번호>` 줄을 넣어 이미지로 MARKS 칸에 넣음 (PI, CI, PL) |

- 청구처(Bill To)·받는 곳·결제 조건·HS 코드는 같은 고객이면 이전 건과 같게 둔다(고객 정보 표의 기본값).
- 품목 줄은 PI·CI·PL 시트에 직접 넣고, 남는 줄은 지우지 않고 숨긴다.
- 발주서의 합계는 다시 계산해서 확인한다. 취소 품목이 합계에 남아 있는 경우가 있다.
- 원본에 로고·서명 이미지가 있으므로 엑셀 라이브러리로 저장하지 않고 파일 내부를 직접 고친다(이미지 보존).

### FX#204에서 영업팀이 고친 점 (반영 완료)
- **무상 품목(교체품 등):** 품명에 `REPLACEMENT:`를 붙이지 않고 일반 품목처럼 `n. UV LAMP (모델)`로 쓴다. **단가는 그대로 적고**, 금액 칸에 소문자 `non-commercial`을 가운데 정렬로 쓴다. 합계 금액에는 들어가지 않는다.
- **Remarks:** 기본 문구 뒤에 한 줄을 띄우고 `Items No. 10,11: No commercial value - free replacements`처럼 품목 번호와 이유를 쓴다.
- **Part#:** 발주서에 `unknown`이어도 PI에는 Part#를 채운다. 모델명 → Part# 표가 필요하다(거래처별, 드라이브에 비공개로 관리).
- **품명:** 모델명 형식이 달라도(예: FS-AAH012) 이 거래처 램프는 모두 `UV LAMP`.
- **MARKS 칸:** 쉬핑마크는 칸이 좁고 길어서, 같은 내용을 세로로 배치한 이미지로 만들어 칸을 채운다(마름모+받는 곳, 목적지, PO NO., SHIPPING MARK, MADE IN KOREA).
- **날짜 (확정):** 인보이스 날짜 = PI 발행일, 출발일 = 인보이스 날짜 + 달력 10일. 예: 발주 6/30, 발행 7/3 → 출발 7/13.

## 구글 드라이브 작업 폴더 (2026-11-23)
회사 구글 드라이브의 `AUTOMATION` 폴더에 거래처 보관함을 그대로 올려서 쓴다. 폴더 주소·ID는 거래처 자료가 있으므로 이 공개 저장소에 적지 않는다.
```
AUTOMATION/
└─ <거래처>_검수후 출고할 것/
   ├─ 1.PO/<연도>/FX#번호/   주문 1건 = 폴더 1개 (발주서, PI, 원본 엑셀, 검수 리스트, CIPL, 송금증, AWB)
   ├─ 2.Quotation  3.Sample Lamp Inquiry  4.Claim  5.R&D Inquiry
   └─ 6.Data  7.Meeting Minutes  8.Contact Person  8.Exclusive Agency
```
1. **메일 스캔:** 회사 메일이 전달되는 Gmail에서 새 발주 메일(제목 `neworder`, 첨부 `Order*.xlsx`)을 찾아 발주서를 내려받는다.
   이미 PI를 보낸 건(같은 스레드에 `*_PI*.pdf` 회신이 있는 건)은 건너뛴다.
   발주서의 Part#가 `unknown`이면 Part# 표 → 과거 PI 순서로 찾고, 없으면 "확인 필요"로 남긴다.
2. 같은 폴더에 결과물을 **새 파일**로 올린다(드라이브 연결은 새 파일 만들기만 가능, 기존 파일 수정 불가). 이름은 기존 파일과 겹치지 않게 `_auto`를 붙인다.
3. 영업팀이 고친 PI가 같은 폴더에 들어오면 차이를 비교해 규칙과 표에 반영한다.

## 실제 완료 건과 비교해서 배운 점 (2026-11-23)
- **원본 엑셀은 마지막(CI) 단계 값으로 덮어쓴다.** 출고 날 CI를 만들면서 인보이스 날짜·출발일을 실제 출고일로 바꾸므로, 완료 건의 엑셀 날짜는 PI 발행 때 날짜가 아니다. PI 날짜 규칙은 `<인보이스>_PI*.pdf`로 확인한다.
- **PO 날짜:** 고객이 수정 발주서(`…Re`)를 보내면 PO 날짜는 수정본을 받은 날로 쓴 경우가 있다(발주서 안의 날짜는 처음 날짜 그대로).
- **발주서에 없는 무상 교체품이 PI·CI에 추가될 수 있다** (클레임 처리분, 핀 같은 부품 포함). 교체품 목록은 `4.Claim`을 함께 봐야 한다.
- **HS 코드는 품목별로 나눈다:** 램프와 다른 부품(예: 핀)이 섞이면 `Items No. 1–10: … / Item No. 11: …`처럼 적는다.
- **운송 방법은 건마다 다르다:** 포워더 항공(EXW) 외에 특송(DHL, DAP)인 건은 운임을 품목 줄(`DHL COST 1 EA`)로 넣고 합계 조건이 `G.TOTAL (DAP)`가 된다.
- **출발일:** 항상 +10일은 아니다. 실제로 +21일로 적은 건이 있다. 규칙(+10일)과 다르면 담당자에게 확인한다.
- **LibreOffice 주의:** Remarks 글이 칸 높이를 넘으면 칸 안의 줄바꿈이 무시된다. 첫 줄 앞 빈 줄을 두지 않는다.
- **실제 사례:** 수식이 반영되지 않아 금액이 틀린 PI가 고객에게 나가 다시 보낸 적이 있다. 자동 작성 후 합계를 발주서 합계와 대조한다.
- **자동 점검이 잡아야 할 실제 실수:** PI의 PO 번호가 이전 건 번호로 남아 있는 경우, HS 코드 표기 형식이 건마다 다른 경우(`8539.49-1090` / `8539.49.1090`), 교체품 순서가 발주서와 바뀐 경우.
