# 호스팅·관리 방식 검토 (2026-11-23)

결정 상태: **보류.** 지금은 GitHub Pages(정적 사이트)를 유지한다. 아래는 나중에 진행할 때 이어서 볼 내용이다.

## 원하는 방향
- 호스팅은 카페24로 옮긴다. GitHub을 거치지 않고 배포하고 싶다.
- 자주 고치지는 않지만, 모든 페이지를 블로그처럼 직원이 직접 고칠 수 있어야 한다.
- 후보: **카페24 + WordPress** (지금 디자인을 테마로 옮기고, 6개 언어·문의·채팅·3D 램프 설계를 유지).

## WordPress로 옮길 때 할 일
1. 카페24 워드프레스 호스팅 신청 (회사)
2. 지금 디자인을 WordPress 테마로 변환: 메뉴, 첫 화면 섹션, 제품·적용 분야·회사 페이지 틀
3. 내용 이전: 한국어 66개 페이지, 제품 40개, 소식 3건, 이미지, 5개 언어 번역(docs/i18n)
4. 기능 연결: 문의(Apps Script 유지), 채팅, Cloudflare Turnstile, 3D 램프 설계, 구조화 데이터
5. 보안: 관리자 2단계 인증, 로그인 시도 제한, 자동 업데이트, 자동 백업, 관리자 주소 변경
6. 직원용 사용 설명서
7. 시험 주소에서 확인 후 도메인 연결

정해야 할 것: 다국어 플러그인(Polylang 무료 / WPML 유료).
한계: 이 작업 환경에서는 카페24에 직접 설치할 수 없다. 테마 파일과 이전 데이터를 만들어 주고, 설치·업로드는 관리 화면에서 한다.
직원이 한국어만 고치면 외국어 페이지는 자동으로 바뀌지 않는다.

## 정적 사이트 그대로 카페24에 올릴 때 (WordPress 이전 전 단계로도 가능)
- 업로드용 zip을 만들어 FileZilla나 카페24 파일관리자로 올린다.
- 도메인 루트용으로 빌드(SITE_BASE 없음), CSP 유지, `.htaccess`에 https 강제·보안 헤더·예전 주소 301.
- 시험용(검색 노출 차단 유지)을 먼저 올려 확인한 뒤 공개용을 올린다.

## 공개 전에 필요한 것 (어느 방식이든 공통)
- 예전 lichtzen.com의 호스팅 위치, 도메인 구입처와 DNS 관리 권한
- 예전 홈페이지 주소 목록 (301 이동용, 예: `shop_contents/myboard_read.htm?...idx=…`)
- 공식 대표 이메일 결정 (홈페이지 ltz@, 코머신 contact@)
- 회사소개 탭 이름 통일 (품질·인증 / 특허·인증 등), 개인정보처리방침 빈칸
- 방문 통계 도구 여부, Search Console·네이버 서치어드바이저 등록 계정
- 공개 날: robots `Disallow`·noindex 해제, sitemap 제출
- 그 전에 할 것: GitHub·회사 Google 계정 2단계 인증, 새 Code.gs 배포, `TURNSTILE_SECRET` 확인
