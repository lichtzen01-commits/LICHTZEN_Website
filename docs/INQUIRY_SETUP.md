# 문의 메일 받기 설정 · 실시간 상담 검토

## 1. 지금 만들어진 것

- **같은 발송 코드:** 오른쪽 아래 문의하기 채팅과 문의 페이지(/contact/)가 모두 `deploy/site/assets/inquiry.js`를 거쳐 **Google Apps Script 수신기**(`integrations/apps-script/Code.gs`)로 보냅니다. 수신기가 회사 메일로 정리해 보냅니다.
- **채팅 순서:** 분야 → 내용(+클립 버튼으로 파일 첨부) → 이메일 → 회사·성함(선택) → 요약 확인 + 개인정보 동의 → 제출.
- **첨부 파일:** 문서·엑셀·파워포인트·한글·사진·도면(DWG·STEP 등)·ZIP 등 대부분 가능. 파일당 10MB, 5개, 합계 20MB까지. 실행 파일(.exe 등)은 막습니다. 메일에 실제 파일로 붙습니다.
- **고객 언어로 응대:**
  - 채팅은 주소의 `?lang=` 값을 먼저 보고, 없으면 **브라우저 언어**를 따릅니다(영·중·일·스페인·힌디). 그 밖의 언어는 영어로 응대합니다.
  - 고객에게는 **그 나라 언어로 접수 확인 메일**이 자동으로 갑니다. 고객의 문의 내용은 확인 메일에 넣지 않습니다. 남의 주소를 넣은 스팸에 악용되지 않게 하기 위해서입니다.
- **메일 형태:**
  - 제목은 `[홈페이지 문의] 분야 · 회사명`입니다.
  - 본문은 **문의 내용**이 먼저 오고, 아래에 분야·회사·이메일·첨부 파일 이름만 작게 붙습니다.
  - 메일에서 **답장**을 누르면 고객에게 바로 갑니다.
- **스팸 방지:** 보이지 않는 함정 칸, 시간당 전체 40건과 같은 이메일 5건 제한, 허용되지 않은 파일 형식 차단.
- **테스트 모드:** `inquiry.js`의 `ENDPOINT`가 비어 있으면 아무것도 보내지 않고 "테스트 사이트라 전송되지 않았습니다"라고 안내합니다.

## 1-1. 문의 목록 자동 정리 (2026-11-19)

- 구글 스프레드시트 **"LICHTZEN 홈페이지 문의 목록"**이 처음 문의 때 자동으로 만들어집니다.
- **연도별 탭**(2026, 2027 …)에 문의가 한 줄씩 쌓입니다. 최신 연도 탭이 앞에 옵니다.
  - 칸: 접수번호(2026-0001…), 접수 시각, 상태, **국내/해외**, 경로, **분류**, 고객이 고른 항목, 회사·담당자, 이메일, 연락처, 관심 제품, 고객 언어, 문의 내용, 첨부 파일 링크, 보낸 페이지, 담당자, 메모
  - **상태:** 접수 / 진행 중 / 견적 발송 / 완료 / 보류 중에서 고릅니다.
  - **국내/해외:** 자동으로 정합니다. 한국어가 아닌 화면에서 왔거나, +82가 아닌 국제번호면 해외입니다. 틀리면 목록에서 바꾸면 되고, 통계도 고친 값을 따릅니다.
  - **분류:** 언어와 상관없이 같은 분류로 모입니다. 램프 교체·소량 제작, LED UV 시스템, 장비·라인 도입, 맞춤 설비 제작, 기술 사양·견적, 경화·건조 품질 문제, 샘플 테스트, OEM 공급, 램프 A/S, 기타입니다.
- **'통계' 탭**은 문의가 올 때마다 자동으로 다시 계산됩니다.
  - 표: 올해 분류별 국내·해외 / 올해 국내·해외 / 연도별 국내·해외 / 연도·분류별 / 월별
  - 그래프: 올해 분류별 문의 수(국내·해외 누적 막대), 올해 국내·해외 비율(원), 연도별 국내·해외(막대), 월별 문의 수(막대)
- 첨부 파일은 드라이브 폴더 **"LICHTZEN 홈페이지 문의 첨부"**에 보관하고, 시트에는 링크를 남깁니다.
- 회사로 오는 문의 메일마다 **전체 목록을 엑셀(.xlsx)로 첨부**합니다. 통계 탭과 그래프도 들어 있습니다.
- 기존 시트·폴더를 쓰려면 `CONFIG.SHEET_ID`, `CONFIG.DRIVE_FOLDER_ID`에 ID를 넣고, 엑셀 첨부를 끄려면 `ATTACH_XLSX: false`로 바꿉니다.
- 코드를 바꾼 뒤에는 편집기에서 `testSend`를 한 번 실행해 새 권한을 승인하고, **배포 관리 → 수정 → 새 버전**으로 배포합니다.

## 2. 실제 메일과 연결하기 (약 10분, 한 번만)

준비물은 문의 메일을 보낼 **Google 계정** 하나입니다. 회사 공용 Gmail을 권장합니다.
- 받는 주소는 ltz@lichtzen.com 그대로 둘 수 있습니다.
- 일반 Gmail은 하루 100통까지 보낼 수 있습니다. 접수 확인 메일을 포함하면 하루 문의 약 50건입니다.
- Google Workspace 계정이면 하루 1,500통입니다.

1. 그 계정으로 https://script.google.com 에 들어가 **새 프로젝트**를 만듭니다.
2. 기본 코드를 지우고 `integrations/apps-script/Code.gs` 내용을 통째로 붙여 넣습니다. 맨 위 `CONFIG.TO`가 받는 주소입니다. **비워 두면 스크립트를 만든 계정의 Gmail로 받습니다**(테스트용). 회사 운영으로 넘어갈 때 `'ltz@lichtzen.com'`을 넣습니다.
3. 위쪽 함수 선택에서 `testSend`를 고르고 **실행**합니다.
   - 권한 승인 창이 뜨면 허용합니다. "확인되지 않은 앱" 경고가 나오면 고급 → 이동을 누릅니다.
   - 그 계정 Gmail로 시험 문의 1통(첨부 test.txt 포함)과 접수 확인 메일 1통이 오면 성공입니다.
4. **배포 → 새 배포 → 유형: 웹 앱**을 고릅니다.
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
   - 배포를 누르면 `https://script.google.com/macros/s/…/exec` 주소가 나옵니다.
5. 그 주소를 알려주시면 제가 `inquiry.js`의 `ENDPOINT`에 넣고, 실제 사이트에서 시험 문의(파일 포함)를 보내 확인하겠습니다.

나중에 바꿀 수 있는 것

- **드라이브 보관:** `CONFIG.DRIVE_FOLDER_ID`에 드라이브 폴더 ID를 넣으면 첨부 파일이 그 폴더에도 쌓입니다.
- **수정 후 반영:** 코드를 고친 뒤에는 **배포 관리 → 수정 → 새 버전**으로 다시 배포해야 반영됩니다. 이렇게 하면 주소는 그대로입니다.
- **개인정보처리방침:** 제5조 위탁(Google LLC, 문의 메일 전달)과 제6조 국외 이전(이전받는 자·국가·항목·목적·기간·거부 방법)을 반영했습니다.

## 3. 실시간 상담 기능 검토

결론: **넣을 수 있습니다.** 다만 응답할 사람과 시간을 먼저 정해야 합니다. 응답이 늦은 실시간 상담은 메일 문의보다 인상이 나쁩니다.

| 방법 | 장점 | 단점 | 비용(대략) |
|---|---|---|---|
| **채널톡** | 국내 B2B에서 많이 씀. 웹 채팅·카카오톡·이메일을 한 화면에서 처리. 모바일 앱으로 응답. 업무 시간 밖에는 자동으로 메일 문의로 전환 | 버튼 디자인이 채널톡 기본형(색은 맞출 수 있음) | 무료 요금제 있음, 유료는 상담원 수에 따라 |
| **카카오톡 채널 1:1 채팅** | 국내 고객이 가장 익숙함. 지금 채팅 창에 "카카오톡으로 상담" 버튼만 추가하면 됨 | 해외 고객은 거의 쓰지 않음. 홈페이지 안이 아니라 카카오톡으로 이동 | 무료 |
| **tawk.to / Crisp** | 해외 고객용으로 무난. 다국어 | 국내 고객에게는 낯섦 | tawk.to 무료, Crisp 무료~유료 |
| **WhatsApp 비즈니스** | 해외 고객(동남아·중남미·인도)에게 익숙 | 국내 고객은 안 씀 | 무료 |

추천 순서

1. **지금:** 메일 접수(위 2번)를 먼저 켭니다.
2. **다음:** 지금 채팅 창에 **"카카오톡으로 바로 상담"** 버튼을 하나 추가합니다. 업무 시간에만 보이게 할 수 있습니다. 해외 화면에서는 WhatsApp 버튼을 보입니다.
3. **문의가 늘면:** 채널톡으로 옮겨 웹 채팅·카카오톡·메일을 한곳에서 처리합니다. 담당자 지정과 응답 시간 통계도 볼 수 있습니다.
4. **AI 답변:** 제품 자료로 1차 답변을 하고 사람에게 넘기는 방식입니다. 서버(또는 서버리스 함수)와 AI API 키가 필요합니다. 채팅 화면은 지금 것을 그대로 씁니다.

회사에서 정할 것: 응답 담당자, 상담 시간(예: 평일 09–18시), 카카오톡 채널 유무, 해외 문의 응대 언어.

## 5. Cloudflare Turnstile (자동 스팸·봇 차단)

채팅과 문의 페이지 전송 직전에 Cloudflare가 사람인지 확인합니다. 대부분 방문자에게는 아무것도 보이지 않고, 의심스러울 때만 "사람입니다" 체크 상자가 나타납니다.

1. https://dash.cloudflare.com 에서 무료 계정 → 왼쪽 메뉴 **Turnstile** → **Add widget**
   - Widget name: LICHTZEN 문의
   - Hostnames: `lichtzen01-commits.github.io` (정식 공개 때 `lichtzen.com`, `www.lichtzen.com` 추가)
   - Widget mode: **Managed**
2. 만들면 **Site Key**(공개용)와 **Secret Key**(비밀) 두 개가 나옵니다.
3. Site Key → `deploy/site/assets/inquiry.js`의 `TURNSTILE_SITEKEY = ''` 따옴표 안에 넣습니다. (공개돼도 괜찮은 값)
4. Secret Key → Apps Script 편집기 왼쪽 ⚙ **프로젝트 설정** → 맨 아래 **스크립트 속성** → 속성 `TURNSTILE_SECRET`, 값에 Secret Key → 저장. **이 값은 코드·저장소·메일에 적지 않습니다.**
5. Apps Script 코드를 최신 `Code.gs`로 바꾼 뒤 **배포 → 배포 관리 → 수정 → 새 버전 → 배포** (주소는 그대로).

- 두 값이 모두 비어 있으면 검사 없이 지금처럼 동작합니다.
- Secret Key만 넣고 Site Key를 안 넣으면 모든 문의가 `(code: captcha)`로 거절되니 순서대로 넣으세요.
- 편집기의 `testSend`는 검사를 건너뜁니다.
